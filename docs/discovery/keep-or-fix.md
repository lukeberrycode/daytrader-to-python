# DayTrader 8: keep-or-fix decisions

Behaviour in the legacy app that is odd, wrong or undocumented. For each: who depends on it, Claude's suggestion, and the decision with its reason. Kept quirks become requirements; fixed ones become requirements for the corrected behaviour. **The decisions are Luke's, at the first gate.**

| ID | Behaviour | Evidence | Who depends on it | Suggestion | Decision |
|---|---|---|---|---|---|
| KF-1 | A buy isn't checked against cash, so the balance can go negative | TRADE-3 test | Benchmark workloads (never fail for lack of cash) | **Fix:** reject a buy that costs more than the cash balance. Keep a setting for load tests if NFR-1 needs it | Pending |
| KF-2 | Registration accepts any opening balance, including negative (non-numeric: untested) | AUTH-4 test | No one | **Fix:** require a positive amount with at most 2 decimal places | Pending |
| KF-3 | A wrong password or an unknown user ID is an HTTP 500. The server log records the password tried **and the user's stored password**, in plain text. Passwords and card numbers are stored in plain text, and the account page puts both in its HTML | AUTH-3, AUTH-9 and AUTH-11 tests; server log checked by hand | No one | **Fix:** a login error on the page (no 500); hash passwords (e.g. Argon2); never log secrets; don't store full card numbers. The migrated data can't be hashed in place, so seeded users get new hashed passwords | Pending |
| KF-4 | Money mostly uses `BigDecimal` half-up to 2 places, with leaks: quote `change` is a `double` (DOUBLE column); `new BigDecimal(double)` builds some constants; JSON sends money as numbers; quantity is a `double` | Code: `QuoteData`, `TradeConfig`, DDL; QUOTE-1 test | API clients reading the JSON | **Fix inside, keep outside:** `Decimal` everywhere internally; keep the JSON field names and numeric format for API clients, or version the API if strings are chosen | Pending |
| KF-5 | Selling an already sold holding is an HTTP 500 (the "cancelled" order it tries to save fails validation); no money moves | TRADE-5 test | No one | **Fix:** a clear message on the order page; no 500 | Pending |
| KF-6 | `web.xml` declares security constraints, but the server enables no application security, so `/config` (reset, rebuild database) needs no login | ADMIN-1 test | Load testers (scripts reset the database) | **Fix:** operator login for `/config`; load-test scripts log in | Pending |
| KF-7 | With the default "long run" setting, a completed order is shown once in an alert and then **deleted**, so order history is always empty. The config page describes long run only as "disabling the show all orders query" | ORDER-1 tests (including one that separates deletion from the hidden-orders query) | Benchmark (stops the order table growing) | **Fix:** keep orders; mark them as alerted instead of deleting. History becomes a real feature | Pending |
| KF-8 | An unknown symbol in the quotes API returns `null` in its place, with HTTP 200 | QUOTE-2 test | API clients | **Fix:** HTTP 404 for a single unknown symbol; omit unknown symbols from a list | Pending |
| KF-9 | The image's `MAX_USERS` and `MAX_QUOTES` (1,000 and 500) don't match the shipped database (500 users, 1,000 quotes). The scenario servlet picks users up to 999, so many of its requests fail. Rebuilding the database makes them match | SCEN-1 test; rebuild checked by hand (ADMIN-4) | The scenario servlet | **Drop:** the new slice seeds its own data, from one setting | Pending |
| KF-10 | Gain percentages are rounded to whole percent but shown with 2 decimal places: the ratio is rounded to 2 places before multiplying by 100. A loss of 0.5% shows as +0.00% | HOME-2 test; `FinancialUtils.computeGainPercent` | No one | **Fix:** compute the percentage, then round it to 2 places | Pending |
| KF-11 | The home page's "total of holdings" is the purchase cost, not current market value, so "sum of cash/holdings" and "current gain" ignore price movement. The glossary says current value | HOME-1 test; `tradehome.jsp` | No one | **Fix:** value holdings at the current price, as the portfolio page and the glossary do | Pending |
| KF-12 | A fractional trade uses the quantity as a binary double (0.1 becomes 0.1000000000000000055…), and the database truncates the new balance toward zero to 2 places. With a positive balance the trader pays up to a cent more (0.1 share at 10.00 costs 25.96, not 25.95) and receives up to a cent less on a sale; with a negative balance the rounding goes the other way | TRADE-7 tests | No one | **Fix:** quantities as exact decimals; round money half-up to 2 places explicitly before saving (NFR-2) | Pending |
| KF-13 | If a holding's price × quantity has more than 2 decimal places (with the quantity as a binary double, so every 0.1-share holding), the home page is an HTTP 500 until the holding is sold: `setScale(2)` with no rounding mode throws | HOME-3 test (predicted from the code) | No one | **Fix:** follows from KF-11 and KF-12 | Pending |
| KF-14 | A quote's low and high never change from the opening price, so the "price range" is always the opening price. The glossary says the session's low and high | QUOTE-4 test | API clients (the fields are in the JSON) | **Fix:** update low and high on each price change | Pending |
| KF-15 | The market index (TSIA) is the mean price of all stocks. The glossary says "a computed index of the top 20 stocks"; a code comment says the top 100 | MARKET-1 test | Market summary readers | **Keep, and correct the documentation:** the mean of all stocks is simple and stable. Or decide what the index should be | Pending |
| KF-16 | A negative, zero, empty or non-numeric quantity is an HTTP 500 rather than a message; no money moves | TRADE-6 test | No one | **Fix:** validate the quantity and show a message on the trade page | Pending |
| KF-17 | A configuration update sets every checkbox setting it doesn't include to off. A script that changes one setting also turns off long run, order alerts and the price streamer, which changes trading behaviour (compare KF-7) | ADMIN-3 test | Operators using the form (it sends every field) | **Fix:** only change the settings a request includes | Pending |
